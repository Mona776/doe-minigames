# 贪吃腊肠 三关版产品需求文档

版本：V1.0  
日期：2026年10月16日  
受众：产品、程序、UI、美术、音频、测试

## 1 产品概述

Doe自动前进，玩家用B键控制顺时针转向。吃骨头得分并增长身体，避开墙壁、石头和自身；每关吃满5根骨头进入下一关，共3关，全部完成后结算。

本文只覆盖三关版「贪吃腊肠」。玩法、数值和按键按当前原型核对；正式资产按本文件的制作规格交付，不以临时素材的造型、精度或文件格式作为生产标准。

### 1.1 阅读分工

- **程序**：第2、3章的规则与状态，第5章动效，第8章验收。
- **UI**：第4、5章的页面、组件、字段与交互。
- **美术**：第6章游戏资产，以及第5章UI图标的制作规格。
- **音频**：第7章BGM范围、音效清单及触发要求。
- **测试**：按第8章检查规则、边界与正式资产接入。

### 1.2 产品与屏幕约束

- 屏幕：1.54英寸，240×240像素，正方形显示区约27.66×27.66毫米。
- 场地：10×10格，每格20×20像素，游戏区域200×200像素，四周为实体墙，不能穿越。
- 操作：A选择、B确定、C返回；局内转向只使用B。
- 一条命，3关；每关5根骨头，全局最多15根；无单局限时。
- 本版不包含历史最高分、排行榜、复活、道具或额外挑战关。

### 1.3 功能范围

| 项目 | 本文的三关版 |
| --- | --- |
| 身体增长 | 每吃1根骨头增长1格 |
| 进度目标 | 每关5根，共3关 |
| 换关 | 身体、方向、场地和本关计数重置；总骨头数保留 |
| 难度变化 | 只在进入下一关时变化，本关内速度和障碍固定 |
| 正常结束 | 碰撞失败，或第3关完成后通关 |
| 主动退出 | 不结算，贝壳和神均为0 |
| 历史最高纪录 | 全部不展示，不需要相关UI资产 |

## 2 程序需求 规则与关卡

### 2.1 每关初始化

每关均执行以下初始化：

1. 根据本关配置生成障碍。
2. Doe恢复3格长度、朝右，头位于零基坐标`(5,4)`，身体向左依次占据`(4,4)`、`(3,4)`。
3. 本关骨头数归零，清空转向缓存；累计骨头数保留。
4. 在未占用的格子生成1根骨头。
5. 播放`3 → 2 → 1 → GO`后开始自动移动。

第一关开始前累计骨头数为0。第二、三关分别从累计5根、10根开始。重新开始一局则所有局内数据重置，从第一关开始。

### 2.2 单键转向与缓存

- B采用按下沿触发，长按只计一次；再次触发必须先松开再按下。
- 一个移动节拍内最多缓存3次有效按下。
- 移动时以本节拍开始时的方向为基准，统一计算最终方向，只执行一次移动，随后清空缓存。

| 本节拍B按下次数 | 最终方向 |
| --- | --- |
| 0次 | 直行 |
| 1次 | 顺时针90°，右转 |
| 2次 | 保持原方向，不允许掉头 |
| 3次 | 顺时针270°，即左转 |
| 第4次及之后 | 忽略，仍按3次处理 |

同一节拍内的三次按键不能拆成“右走一格、再下走一格、再左走一格”。跨越节拍边界的输入归属各自到达的节拍，不回滚已经发生的移动。头部附近的方向箭头实时表示下一步实际方向，包含“两次不掉头”的处理结果。

### 2.3 移动、吃骨头与碰撞

每个移动节拍进入相邻1格，顺序为：计算方向、检查目标格、移动、处理吃骨头与过关。

- 未吃到骨头：尾巴前进，身体长度不变。
- 吃到骨头：本关计数和累计计数各+1，身体长度+1，尾巴本步不离开。
- 身体长度始终等于`3 + 本关已吃骨头数`，不能使用累计总数计算长度。
- 头部越过场地边界、进入障碍格、进入未离开的身体格，均立即结束本局。
- 未增长时，允许进入尾巴本步即将离开的格子，不判自撞。
- 一次移动只处理一次食物和一次计数。第5根触发过关或通关，不再生成下一根食物。

### 2.4 关卡配置

| 关卡 | 本关目标 | 每格移动耗时 | 障碍目标段数 | 每段长度 | 障碍目标总格数 |
| --- | --- | --- | --- | --- | --- |
| ROUND 1 | 5根 | 550ms | 0 | — | 0 |
| ROUND 2 | 5根 | 470ms | 2 | 3格 | 6 |
| ROUND 3 | 5根 | 400ms | 3 | 3格 | 9 |

障碍为横向或竖向连续3格。关卡开始时随机生成，整关内位置不变；吃骨头不会在本关内追加障碍或改变速度。配置是目标数量，遇到无法公平放置的情况允许少放。

### 2.5 食物与障碍生成

**食物：**每次只存在1根，不能与身体或障碍重叠。优先从与头部曼哈顿距离≥3的空格中随机生成；没有合适远格时放宽至其他空格。

**障碍：**每关重新生成，必须满足：

- 出发所在整行，即零基`y=4`，不放障碍。
- 不同障碍段不能相邻，含对角相邻；同一段的3个格子连续。
- 仅以障碍划分场地时，全部空格连通，每个空格至少有两个四邻接空格，避免静态死胡同。
- 每段最多尝试100次；无法放置时少放该段，不无限重试，不强行破坏公平条件。

静态场地公平不代表身体形成的临时围堵一定可解。障碍只在每关初始化时生成，运行中不追加。

## 3 程序需求 流程与结算

### 3.1 完整流程

小游戏菜单 → 游戏入口 → 开始游戏 → ROUND 1倒计时 → 第一关 → 换关提示 → ROUND 2倒计时 → 第二关 → 换关提示 → ROUND 3倒计时 → 第三关 → 全部通关结算。

任意关内发生碰撞则进入失败结算，不进入后续关卡。主动退出直接返回小游戏菜单，不经过结果页。

### 3.2 倒计时与换关

- 每关的3、2、1各持续1秒，GO持续0.5秒；期间不移动，A、B无效。
- 倒计时展示本关场地及`ROUND n`、骨头`0/5`。数字不能遮住初始头部和紧邻行进路径；数到1时数字降至约40%不透明度，让玩家看清障碍布局。
- 第一、二关吃到第5根后，停止移动并进入2秒换关提示：前1秒“本关完成”，后1秒分别显示`ROUND 2`或`ROUND 3`。
- 2秒结束后初始化下一关，重新倒计时。换关提示期间仍是上一关场地，下一关场地在初始化后显示。
- 不增加每关开场规则说明，不增加“出现障碍、速度加快”等教学弹页。
- 第三关吃到第5根后直接显示通关结果，不再出现换关提示或第四关倒计时。

### 3.3 各状态的按键

| 状态 | A | B | C |
| --- | --- | --- | --- |
| 游戏入口 | 切换开始游戏/玩法说明 | 打开所选项 | 回小游戏菜单 |
| 玩法说明 | 无操作 | 开始第一关 | 回入口并选中玩法说明 |
| 倒计时、换关提示 | 无操作 | 无操作 | 打开退出确认 |
| 关内移动 | 暂停 | 缓存一次转向 | 打开退出确认 |
| 暂停 | 继续 | 无操作 | 直接退出，无奖励 |
| 退出确认 | 切换两个选项 | 执行所选项 | 取消并返回原状态 |
| 失败或通关结果 | 无操作 | 从第一关再来一局 | 回游戏入口 |

暂停页的C直接退出，退出确认框只用于运行、倒计时和换关状态；两条退出路径均不给奖励。结果页C回入口，与主动退出回小游戏菜单不同。

### 3.4 暂停、确认和系统行为

- A只在移动与暂停之间切换。暂停停止规则计时，继续后从当前位置开始一个完整移动节拍，已缓存转向保留。
- 退出确认标题为“退出本局？”，说明为“退出不获得奖励”；选项“继续游戏”“确认退出”，默认继续。
- 确认期间冻结移动、倒计时和换关计时；取消后恢复打开前的状态及剩余时间，不补走弹窗期间的时间，转向缓存保留。
- 若按C时规则推进已发生碰撞或通关，优先进入正常结算，不再显示退出确认。
- 碰撞反馈持续约0.9秒后显示失败结果；通关直接显示通关结果。
- 结果显示后0.8秒内忽略B，防止连按重开；C可返回入口。
- 游戏、暂停、换关、确认和结果页不执行10秒无操作退出；入口与说明页沿用系统10秒无操作回主界面。
- 正式设备游戏流程保持亮屏。异常强退或断电不补发未结算奖励，不恢复未完成对局。

### 3.5 星级和奖励

| 结束方式或累计骨头数 | 星级 | 贝壳 | 神 |
| --- | --- | --- | --- |
| 碰撞失败，0–4根 | 0星 | 5 | +0 |
| 碰撞失败，5–9根 | 1星 | 10 | +1 |
| 碰撞失败，10–14根 | 2星 | 20 | +2 |
| 全部通关，15根 | 3星 | 30 | +3 |
| 主动退出，任意进度 | 不结算 | 0 | +0 |

- 星级按累计骨头数计算，相当于已经完成的关卡数；不按当前关骨头数、存活时间、身体长度或按键次数计算。
- 例：第二关吃了3根后失败，累计8根，结果为1星、10贝壳、神+1。
- 两次换关均不发奖；奖励只在最终失败或通关时发放一次。即使已经完成前两关，主动退出也不领取阶段奖励。
- 结果页显示累计骨头数、星级和贝壳；神由后台结算，不在结果页显示。
- 本版没有历史最高分、破纪录提示或最高纪录保存需求。

## 4 UI需求 页面与状态

本章交付给UI设计及界面程序。页面按240×240制作，采用已确认的复古像素街机方向；文字解释操作和结果，图标表达骨头、奖励及星级。所有页面使用统一的组件风格，数据字段与页面状态按本章定义。

### 4.1 页面清单

| 页面 | 必须内容 | 交互与变体 |
| --- | --- | --- |
| 游戏入口 | 贪吃腊肠标题或对应标识、角色展示、开始游戏、玩法说明 | 默认开始；A切换、B确定、C返回菜单；不显示历史纪录 |
| 玩法说明 | B一次右转、同一拍三次左转、两次不掉头；每根增长、碰撞结束、每关5根共3关 | 图示配短句；B开始、C回入口；不展示模拟器键盘映射 |
| 每关倒计时 | 3、2、1、GO四个状态、当前ROUND、0/5、本关场地 | 三关均覆盖；第2关2段障碍，第3关3段障碍；最后一秒场地可辨 |
| 关内界面 | ROUND 1/2/3、骨头图标＋本关n/5、场地和下一步方向箭头 | 覆盖三种关卡状态，骨头计数为本关进度 |
| 换关提示 | 本关完成 → ROUND 2；本关完成 → ROUND 3 | 复用简单提示组件，自动继续；不加规则说明页 |
| 暂停 | 压暗场地、暂停、A继续、C退出 | 不增加“A选择、B确认”菜单；C退出不给奖励 |
| 退出确认 | 退出本局？、退出不获得奖励、继续游戏、确认退出 | 普通与选中状态；A切换、B确定、C取消，默认继续 |
| 失败结果 | 本局结束、累计骨头数、三颗星的明暗、贝壳、B再来一局、C返回 | 0/1/2星三个变体；不写撞墙、撞障碍或撞自己的原因文字 |
| 通关结果 | 全部通关、累计15根、三星、30贝壳、B再来一局、C返回 | 与失败结果共用基本布局，替换标题与奖励状态；不显示新纪录 |

### 4.2 信息口径

- 左上写`ROUND 1`、`ROUND 2`、`ROUND 3`，表示当前关卡。
- 顶栏骨头`n/5`仅表示本关进度，换关归零；结果页骨头数表示全局累计，范围0–15。
- 星级只在结果中展示；局内顶栏展示当前关卡与本关骨头进度。
- 页面名称、功能说明和资源编号标在画板外，不占实机屏幕。

### 4.3 必须覆盖的设计状态

1. 入口“开始游戏”和“玩法说明”两种焦点。
2. 第一关完整倒计时3/2/1/GO，以及第2、3关带障碍的倒计时布局。
3. ROUND 1/2/3三种关内布局，障碍分别为0/2/3段。
4. 两次换关提示：进入ROUND 2和进入ROUND 3。
5. 暂停及退出确认两种焦点。
6. 失败结算0星、1星、2星，以及三星通关。

资源和页面均组件化，不为上述状态重复绘制相同面板或图标。

## 5 UI需求 组件与动效规格

### 5.1 视觉和排版

复古像素硬边；深蓝底、低对比棋盘格、青绿色边框、暖金焦点和米白正文。所有页面使用统一视觉规范，正式设计不要求复刻临时素材。

建议色板：背景`#081923`，棋盘`#0D2633 / #123241`，边框`#66C7B5`，分隔`#244D58`，强调`#F3C04F`，正文`#F4EDD6`，次要文字`#8DA5AD`。状态同时通过文字、形状或轮廓区分，不能只靠颜色。

场地左上角为`(20,30)`、尺寸200×200；墙线放在外围，不占用格子。顶栏位于场地上方。文字、按钮等关键内容距屏幕边缘至少12像素；正文采用12像素、标题24像素的可合法交付像素字体。

### 5.2 UI资源清单

| 组件或资源 | 制作与交付规格 |
| --- | --- |
| 游戏标题 | 独立标题组件，建议控制在160×48像素以内；入口角色使用正式游戏部件拼接，不另出整身立绘 |
| 背景 | 可平铺40×40像素棋盘纹理或程序绘制；文本与计数不烘焙进背景 |
| 面板和按钮 | 按钮建议宽132–150像素、高24–30像素；提供普通/选中态。弹窗与面板可伸缩，边框和填充分离 |
| 计分图标 | 骨头图标16×16；用于n/5及结果计数 |
| 奖励图标 | 贝壳16×16；星星基准9×9，未获得/已获得两态，结果页可整数放大至27×27 |
| 按键标识 | A/B/C各16×16，字母可辨；标签旁配简短动作词，不用纯符号替代全部说明 |
| 方向与教程图标 | 局内箭头10×10，支持四向；教程右转/左转/直行各18×18，可复用或旋转生成 |
| 倒计时与换关标题 | 3/2/1建议在28×36区域内；GO用24像素字号；“本关完成”和ROUND 2/3使用同一提示组件 |
| 字体 | 12及24像素字号，覆盖本文UI文案、数字、ASCII和标点；交付字库及授权说明 |

正式UI稿可以在上述范围内调整面板排版，但不能改变200×200场地、按键功能或数据口径。设计交付为独立Pixso文档中的可编辑页面、组件、状态、尺寸标注与导出清单；无需导出带固定数字的整屏图片。

### 5.3 程序动效

| 事件 | 表现与时序 | 制作边界 |
| --- | --- | --- |
| 骨头生成 | 约250ms弹出；平时每600ms上下浮动2像素 | 只需1张骨头原图，位移与缩放由程序完成 |
| 吃到骨头 | 碎屑约320ms消散，进度数约250ms弹动、400ms高亮 | 不需要为每个分数绘制帧图 |
| 行走 | 前后脚错相循环，每格移动分4段切换姿态 | 使用第6章两组脚动画，按本关速度驱动 |
| 倒计时 | 3/2/1/GO按第3章时序；数字1降至约40%不透明度 | 场地保持可见，不烘焙数字进场景 |
| 换关 | 2秒内分两段显示本关完成、下一关ROUND | 不额外增加操作，不增加加载条 |
| 碰撞 | 场地短震约320ms，角色闪烁、头部眩晕符号及碰撞处高亮；约900ms后结果 | 三种碰撞共用反馈体系；不新增原因插图或原因文字 |
| 全部通关 | 第15根触发结果与通关音效，三星及贝壳明确可见 | 不强制等待一段额外庆祝动画，不另设奖励领取页 |

## 6 美术需求 正式游戏资产

### 6.1 角色与制作原则

制作可拼接的Doe侧面腊肠狗。头、身体、转角和尾部能形成连续轮廓；共四只脚，前脚随头、后脚随尾，身体变长时两对脚自然分开。应有清楚的行走感，直线与转弯都能辨认方向。

三个关卡共用一套正式资源，不需要分别绘制角色、骨头或石头。尺寸是正式制作约束，不要求复刻临时素材造型。

### 6.2 游戏资产清单

| ID | 资产 | 最终屏幕尺寸 | 数量 | 制作要求 |
| --- | --- | --- | --- | --- |
| A01 | 头部 | 20×20 | 1张 | 基准朝右，面部可辨，脖子接口与身体一致 |
| A02 | 直线身体 | 20×20 | 1张 | 可无缝重复拼接，横竖由程序旋转，接缝不露底 |
| A03 | 直角身体 | 20×20 | 1张 | 90°弯角，可覆盖四种转角组合，与直线身体粗细、接口一致 |
| A04 | 尾部 | 20×20 | 1张 | 与身体连续衔接，尾部轮廓可辨，不随长度另画整身 |
| A05 | 前脚组 | 24×24 | 2帧 | 包含近侧、远侧两只前脚，锚定头部，姿态循环形成迈步感 |
| A06 | 后脚组 | 24×24 | 2帧 | 包含近侧、远侧两只后脚，锚定尾部，与前脚错相播放 |
| A07 | 骨头食物 | 20×20 | 1张 | 视觉主体位于格内，与角色和石头易区分 |
| A08 | 障碍石头 | 20×20 | 1张 | 可重复横排或竖排3格；轮廓与实际占格一致 |
| A09 | 眩晕符号 | 6×6 | 1张 | 小星或眩晕标记，供程序绕头部运动 |

尺寸均以240×240屏幕中的最终像素计。脚层可四边各伸出格块2像素，中心锚点为24×24画布的`(12,12)`，不改变碰撞范围。20×20资源是正式导入基准，程序负责运行时适配。

### 6.3 拼接与动画验收

- 以朝右为基准交付，验证旋转、镜像后的四向效果。
- 附直线、连续弯角、头接弯角、尾接弯角的拼接校验图，标明连接接口、锚点与透明区。
- 前后两组脚错相循环；暂停、倒计时和换关使用站立帧；身体变长只增加身体格，不增加脚。
- 关卡重置后，长度回到3格，头尾与脚应立即正确归位，不能残留上一关长身体。
- 不另画任意长度的完整狗、各方向整身动画、三套关卡角色或三套石头。
- 骨头弹出、碎屑、闪色、场地震动和眩晕轨迹由程序实现，不要求提交整段帧动画。

### 6.4 交付格式

交付可编辑像素源文件、透明PNG单帧及资源清单。原生1倍导出，无抗锯齿、无模糊缩放、无JPEG；不把扫描线、机壳或文字烘焙进游戏素材。

资源按`asset_id + 帧序号`命名，清单记录画布尺寸、锚点、默认方向、帧顺序和循环方式。UI面板、图标和字体按第5章交付，不混入角色资源；三个关卡复用同一资源时保持资产ID及版本一致。

## 7 音频需求 BGM与音效

### 7.1 BGM范围

本版采用关键事件音效反馈，**不要求独立BGM，作曲无需新增循环曲目**。

音色保持复古街机感，短促、清晰，失败和通关可明显区分。走路、普通转向及连续按B不播放音效，避免密集操作变成噪声。

### 7.2 音效清单

以下时长为正式制作建议，具体节奏需匹配触发点，不要求复刻原型旋律或音高。

| ID | 事件 | 建议时长 | 触发与制作要求 |
| --- | --- | --- | --- |
| S01 | 吃到骨头 | 50–150ms | 短促积极反馈；普通吃骨头时一次。第5根触发过关或通关时由对应音效替代 |
| S02 | 倒计时 | 约90ms | 三关的3、2、1共用，数字切换时播放 |
| S03 | GO | 约330ms | 比倒计时更明确明亮，GO出现时播放；三关共用 |
| S04 | 本关完成 | 约700ms | 第一、二关第5根触发，上扬且简短；两次换关共用 |
| S05 | 全部通关 | 约1.8秒 | 第三关第5根触发，完成感明显；在通关结果显示时可继续播放，不阻塞结果页 |
| S06 | 碰撞失败 | 约560ms | 墙、障碍、自撞共用；清楚但不过分刺耳 |
| S07 | 暂停与继续 | 约100ms | 两次状态切换可复用，不能被识别为失败或过关 |

### 7.3 触发与交付要求

- 同帧只播放最高优先级事件：最终结束（通关或碰撞）> 本关完成 > 普通吃骨头。
- 主动退出不播放碰撞失败或通关音效，不发出奖励到账声。
- 本版没有局内得星、破纪录、加速播报音效；星级为最终结算信息。
- 音效不因长按重复触发；快速重开或返回时及时终止上一局残留的事件音，避免串到新一局。
- 交付单声道44.1kHz、16-bit PCM WAV与音频源工程；如需兼容合成播放，另交音高/时值事件表。
- 所有资源无削波、无首尾爆音，程序统一控制增益；不将低音量烘焙进母带。
- 程序根据最终硬件能力确认运行格式，并在真机检查提示音清晰度和连按状态下的播放优先级。

## 8 验收与交付检查

### 8.1 规则验收

| 检查项 | 通过标准 |
| --- | --- |
| 单键转向 | 同一节拍1次右转、2次直行、3次左转、第4次忽略；长按不连续转向，跨节拍归属正确 |
| 增长 | 每根骨头都增长1格，单关长度为3加本关骨头数，换关后恢复3格 |
| 碰撞 | 撞墙、石头或身体均失败；允许进入本步离开的尾格 |
| 关卡切换 | 第5、10根分别换关，第15根立即通关；换关重置身体、方向、障碍、本关计数与转向缓存，累计计数保留 |
| 关卡数值 | 三关速度分别550/470/400ms，目标障碍分别0/2/3段，每段3格；本关内不变化 |
| 公平生成 | 出发整行无障碍，不同段不相邻，静态空地连通且无死胡同；骨头不压身体或石头 |
| 倒计时 | 每关都有3/2/1/GO，角色不提前移动；第2、3关障碍在最后一秒清楚可辨 |
| 暂停与确认 | 暂停不移动，继续获得完整节拍；确认框冻结包括换关在内的计时，取消不补走时间 |
| 同帧边界 | 打开退出确认前已经碰撞或通关时走正常结算，不弹无奖励提示，不重复发奖 |

### 8.2 结算验收

| 场景 | 预期 |
| --- | --- |
| 第一关吃到4根后失败 | 累计4根，0星、5贝壳、神+0 |
| 第二关吃到3根后失败 | 累计8根，1星、10贝壳、神+1 |

### 8.3 正式资产与UI验收

- 在1.54英寸真机按原尺寸检查文字、数字和图标，不仅检查放大模拟器。
- ROUND、本关n/5和结果累计总数口径正确；不展示历史最高分、奖杯数字或新纪录。
- UI覆盖三关、两次换关、退出确认、0/1/2星失败和三星通关；无额外开场规则页。
- 四向角色拼接无缝，四脚数量与位置正确；成长时前后脚分开，换关恢复3格后归位。
- 在正常可放置样例中，第二关表现2段障碍、第三关3段，不以一段示意图代替完整场地验收。触发生成降级时按实际障碍格绘制，不补画不存在的障碍。
- 所有音效触发准确；通关音效与失败音效可辨，不被普通吃骨头音覆盖。

### 8.4 正式接入事项

本文的规则和数值按原型核对；正式UI和资产接入不能仅以“模拟器中已存在”代替验收。当前程序需重点检查：

1. 以正式PNG部件替换素材时，适配20×20基准、脚层锚点和四向拼接。
2. 根据正式Pixso组件完成三关、两次换关及结果变体；保持现有按键与页面跳转语义。
3. 将音频制作用母版适配到设备播放链路；快速重开、返回时清理上一局音效。
4. 贝壳和神通过正式养成服务结算，单局只到账一次；换关和主动退出不提交奖励。
5. 真机验收资源内存、字库、纹理格式和音频解码预算；不能假定桌面可用格式可直接在设备运行。

程序、美术、UI和音频分别按对应章节交付。正式制作阶段如需改动数值、交互或资产规格，应同步更新本文件和验收样例。
